### Deviations (documented for senior review)

- **D1 — "No prop contract" → module-level component with props.** The plan says the dock "closes over existing state — NO prop contract" (defined inline). An inline component would remount on EVERY reader re-render (scroll-spy `activeKey`, settings, panel toggles), which (a) drops the expander state while scrolling, (b) breaks the documented `opener.isConnected` focus-restore (opener node gets detached on remount), (c) loses keyboard focus after any dock click. The plan's own precedent (NotesPanel/BookmarksPanel) is module-level with props, and the plan's a11y requirements (focus restore, Escape+focus return) only work with a stable identity. Implemented module-level with an explicit `ReadingDockProps` (20 fields) — no new file, no shared abstraction; handlers are `useCallback`d in the reader.
- **D2 — Section labels clamped to `max-w-11 truncate`.** Unclamped, "เครื่องมืออ่าน" (59px at 9px) widened the dock to 77px vs the 44px-button spec; clamped, dock = 62px and the `pr` clearance math holds. Full label remains in `role="group" aria-label` + each button's `aria-label`.
- **D3 — Caps on dock root, scroll on group-2 region** (task text said "expander max-h…"). If ONLY the expander had the caps, the fixed chrome (group-1 ≈294px + chevron) plus a `calc(100vh-14rem)` expander exceeds the viewport at 900px height (dock top would be off-screen). Root gets the caps + group-2 `flex-1 min-h-0 overflow-y-auto` → group-1/chevron always visible, group-2 scrolls internally; measured caps match spec exactly.
- **D4 — Clearance `pr-14 md:pr-24` instead of `pr-14 lg:pr-16`.** Measured: 62px dock at `md:right-10` starts at `vw−102`; text column ends at `vw−16`; the spec'd pr-16 left **18px of text under the dock at 1024px** (violates the acceptance "no text under dock at 1024px"). Required clearance = 86px at md+; `md:pr-24` (96px) clears 768/1024 by 14px. Mobile keeps pr-14 (14px FAB overlap at 360px — standard mobile pattern, acceptance names 1024 only). Plan's dock-span estimate (~964–1020) was off by ~40px.
