# Feature Report: Subscription Renew/Cancel + Expense Breakdown

**Version:** v1.9.23 | **Date:** 2026-05-28 | **Component:** Finance Tracker

---

## Summary

Added Renew (create expense + advance billing date) and Cancel (deactivate) buttons to active subscriptions, a collapsible cancelled subscriptions section, and an expense breakdown in the summary showing total expense + subscription portion.

---

## Changes

### 1. SubscriptionList.tsx — Renew/Cancel/Show Cancelled

**File:** `src/components/boss478/finance/SubscriptionList.tsx`

**Renew button:**
- Visible on active subscriptions only
- PATCH-first order: advances `nextBillingDate` by one billing cycle (PATCH `/api/subscriptions`), then creates expense transaction (POST `/api/transactions`) with subscription's amount/category/name as description
- Button shows spinner while in progress, disabled during operation (prevents double-click duplicates)
- PATCH-first ensures retry-safe: if POST fails, date is already advanced so retry creates expense without duplicate

**Cancel button:**
- Sets `active: false` via PATCH `/api/subscriptions`
- Moves sub to cancelled section

**Cancelled section:**
- Collapsible, collapsed by default with count badge: "Show cancelled subscriptions (N)"
- Dimmed/opacity-60 items with no action buttons except delete
- Separate state (`showCancelled`) for collapse toggle

**Helper function:** `advanceBillingDate()` handles weekly (+7d), monthly (+1m), quarterly (+3m), yearly (+1y) using native JS Date

### 2. FinanceSummary.tsx — Expense Breakdown

**File:** `src/components/boss478/finance/FinanceSummary.tsx`

Added a second row to the Expense card:
```
Expense ฿500   (text-xl)
Subscription ฿125  (text-xs, below)
```

The subscription total comes from the existing `subscriptionTotal` computed by `FinanceClient.fetchSummary()` — which applies `MONTHLY_NORMALIZER` to all active subscriptions.

---

## API Surface

No backend changes. All operations use existing endpoints:
- `POST /boss478/finance/api/transactions` — creates expense
- `PATCH /boss478/finance/api/subscriptions` — updates `nextBillingDate` or `active` status

---

## Scrutiny Findings

**Addressed before implementation:**
1. **PATCH-first order** — prevents duplicate expense on retry after partial failure
2. **Button disabled state** — `renewingId` tracking prevents double-click races

**Accepted:**
3. Month-boundary date drift for non-31-day months (e.g., Jan 31 + 1mo = Mar 3) — acceptable for personal tool v1
