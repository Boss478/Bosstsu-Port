## Changed Files

- `src/hooks/useReaderStorage.ts` (+49/−13) — the ONLY file touched:
  - Removed the strict all-or-nothing guard `isReadingSettingsValue` (dead after this change).
  - Added exported `validateReadingSettings`: valid enums pass through; invalid fontSize ('xs'/'L'/…) → 'm'; invalid width ('huge'/…) → 'normal'; missing fields → defaults; null/undefined/non-object → `DEFAULT_READING_SETTINGS`; lineHeight clamped to [1.5, 2.2], non-number/non-finite → 1.8.
  - Added exported `loadGlobalSettings` (reads `krulaw:settings` via `safeGetJSON`; null when missing OR unparseable JSON; any parsed value sanitized through the shared validator) and `saveGlobalSettings` (writes JSON under `krulaw:settings` via `safeSetJSON`).
  - Hook's settings lazy-init now: `validateReadingSettings(safeGetJSON(keys.settings))` — one validator everywhere. `settings`/`setSettings` API + behavior unchanged (per-field sanitization now instead of strict reject; both land on defaults for garbage).
  - **Key scope note**: the global `SETTINGS_KEY = 'krulaw:settings'` (unconditional in `keys.settings`) was already introduced by commit 99613c3 ("device-wide settings"); this lane verified it matches plan §4.5 exactly and preserved it. Bookmarks/lastPosition/notes/highlights remain `${prefix}${KEY_BASES.*}` (per-law). No migration needed — old per-law settings keys are silently ignored (plan-sanctioned).

## Behavior Contract

- `krulaw:settings` is the ONE settings key for every law; reading prefs survive law switches.
- Bookmarks/notes/highlights/lastPosition remain law-scoped (`krulaw:<slug>:*`).
- Any stored settings value (however malformed) read through the hook or `loadGlobalSettings` is sanitized to a valid `ReadingSettingsValue` — never returned raw.
- `setSettings` writes exactly what the UI passes (typed value); no write-side sanitization added (signature-pinned by contract).
- Edge decision: a stored literal JSON `null` at `krulaw:settings` (`JSON.parse` succeeds → `null`) is returned as `null` by `loadGlobalSettings` (indistinguishable from missing; not pinned by the tests). Everything else that parses (e.g. `42`) goes through the validator → defaults.
