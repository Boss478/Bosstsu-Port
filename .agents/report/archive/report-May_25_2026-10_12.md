## Key Lessons

1. **serializeDoc type bridge**: Returning `T` from `serializeDoc(T)` causes `as Array<{_id: string}>` to fail because TypeScript preserves Mongoose `ObjectId` type. Fix: use `as unknown` bridge at page.tsx cast site.

2. **fetchPublished scope**: Best as a focused utility wrapping `model.find() + countDocuments()` in try/catch. Pages still own their own distinct queries, mapping, and rendering — prevents over-abstraction.

3. **Games page is structurally different** from portfolio/gallery/resources (category→tags, Game.distinct→Tag.distinct, createdAt→date sort). Excluded from fetchPublished helper (Option A from Scrutiny).

4. **All build warnings are pre-existing**: Turbopack root detection, upload.ts dynamic path pattern (15K+ matches), duplicate sessionCode Mongoose index. None introduced by Phase 5.

## Scrutiny Impact

The Scrutiny review prevented 3 issues:
- **5.9 justification**: Dockerfile RUN command only affects image layer, not bind-mounted volumes — fixed the rationale (still safe to remove as dead code)
- **5.3 lightbox architecture**: Plan had per-photo lightbox state islands — corrected to single wrapper pattern
- **5.6 games exclusion**: Games page uses different schema (category-based filters, Game.distinct(), createdAt sort) — excluded from the shared helper
